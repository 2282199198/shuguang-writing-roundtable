# 曙光圆桌写作会议发布闭环清单

本清单用于每次公开版本发布。它把“功能完成”“格式兼容”“平台实测”和“公开发布”分开，避免旧验收记录继续代表新版本。

## 1. 版本定义

- [ ] 明确版本号、目标用户、目标宿主和本轮变更范围。
- [ ] 选择并公开成熟度：`LOCAL_PILOT`、`PLATFORM_VERIFIED`、`PUBLIC_BETA` 或 `STABLE`。
- [ ] 写清楚本轮已证明、尚未证明和明确不支持的能力。
- [ ] 不把“采用通用格式”写成“所有宿主均已实机验证”。

## 2. Git 起点

发布修改必须从远端默认分支开始：

```powershell
git fetch origin
git merge-base --is-ancestor origin/main HEAD
git status --short --branch
```

- [ ] 当前版本分支基于 `origin/main`，或有明确、可审计的合并关系。
- [ ] 工作树中没有来源不明的改动。
- [ ] 不使用 `git reset --hard`、强推或静默覆盖解决历史分叉。
- [ ] 本地旧分支需要整理时，先备份并取得明确授权。

## 3. 公共包边界

- [ ] 标准入口为 `skills/shuguang-writing-roundtable/SKILL.md`。
- [ ] 旧单数 `skill/` 路径为 0。
- [ ] Skill 内只有执行所需的 `SKILL.md`、`agents/`、`references/`、`scripts/` 和 `assets/`。
- [ ] 用户文档、版本记录和发布过程文档位于仓库根或 `docs/`，不塞进 Skill 目录。
- [ ] 仓库不包含私人笔记、用户稿件、绝对私人路径、账号凭据、Token、专有提示词或未授权第三方原文。
- [ ] 仓库根 `LICENSE` 和 Skill 内 `LICENSE.txt` 存在。

## 4. 触发与宿主说明

- [ ] `description` 同时写清楚能力、适用场景、常用自然语言和不适用边界。
- [ ] README 同时提供自然语言调用和显式调用方式。
- [ ] 自动触发被表述为宿主语义判断，不承诺机械关键词百分之百命中。
- [ ] `references/host-compatibility.md` 与当前宿主安装方式一致。
- [ ] `agents/openai.yaml` 只作为可选适配层，核心流程不依赖它。
- [ ] 没有工具时的降级交付和禁止冒充规则清楚可执行。

## 5. 本地质量门

在仓库根运行：

```powershell
python -B -X utf8 -m unittest discover -s tests -v
python -X utf8 skills/shuguang-writing-roundtable/scripts/validate_theme_catalog.py
gh skill publish --dry-run
```

另外分别对工作 Skill 和公开包 Skill 运行当前 `skill-creator` 提供的 `quick_validate.py`。

- [ ] 自动化测试全部通过，并记录通过数。
- [ ] 两份 Skill 快速校验均通过。
- [ ] 主题目录校验通过，并记录主题数与图片数。
- [ ] 工作副本与公开副本的核心文件内容一致。
- [ ] `SKILL.md` 保持精简，详细规则按需加载。
- [ ] 发布预检退出码为 0；所有警告均修复或形成书面接受决策。

## 6. 真实任务验证

- [ ] 快速成稿：明确输入时不制造多余追问。
- [ ] 事实核查：能阻止未经证实的高影响结论。
- [ ] 局部修订：锁定内容逐字保持。
- [ ] 知识型公众号长文：内容、证据、标题、摘要和正文层级成立。
- [ ] 公众号公开终稿：默认不出现文末参考资料列表，内部证据仍保留。
- [ ] 微信粘贴片段与手机预览分开，不能把预览网页冒充粘贴片段。
- [ ] 使用真实用户材料时保留来源文件，不回写、不打包、不泄露。

## 8. 提交与标签

- [ ] 文件清单、测试结果和版本说明已复核。
- [ ] 提交信息能说明用户可见变化。
- [ ] 标签指向预期提交。
- [ ] `main` 更新为快进或经过明确评审的合并，不覆盖远端历史。
- [ ] 发布说明包含主要变化、安装方式、验证结果和已知边界。

提交、推送、创建标签和发布 Release 都是外部或版本控制写入动作，必须取得当前批次的明确授权。

## 9. 远端验收

发布后独立核对：

- [ ] `refs/heads/main` 指向预期提交。
- [ ] 标签 peeled commit 与预期提交一致。
- [ ] Release 页面可访问并显示正确版本与成熟度。
- [ ] 标准源码 ZIP 可以实际下载。
- [ ] 直接读取 ZIP 条目，核对文件数、标准入口、许可证、宿主指南和旧路径数量。
- [ ] 记录 ZIP 大小和 SHA-256。
- [ ] 从公开仓库安装固定版本到独立临时目录。
- [ ] 安装后核对 `SKILL.md`、许可证和宿主指南。
- [ ] 临时目录清理后，发布工作树仍为 clean。

Windows 下优先读取 ZIP 目录条目，不在深层中文路径完整解压，以避免路径长度干扰验收。

## 10. 证据同步

- [ ] 更新 `evidence/skill-validation/shuguang-writing-roundtable/public-release-audit.md`。
- [ ] 审计中的版本、提交、文件数、测试数、ZIP 哈希和安装结果与远端一致。
- [ ] 更新复盘行动项状态。
- [ ] 对外说明区分已证明、推断和待验证。
- [ ] 下一位维护者只读这些文件即可知道当前真实状态，不必重放聊天记录。

## 11. 发布完成定义

只有以下条件同时成立，才可以说“这个版本已经发布完成”：

1. 本地测试与 Skill 校验通过；
2. Git 历史和标签正确；
3. Release、ZIP 和远程安装实际可用；
4. 验收记录已经同步到当前版本；
5. 未验证的宿主、用户体验和平台能力被明确保留为限制。

“发布完成”不自动等于“所有宿主稳定”“所有用户都顺手”或“内容效果已经得到真实读者证明”。
