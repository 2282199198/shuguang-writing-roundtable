## 1. 何时启用

以下任一情况启用本协议：

- 主题对当前 Agent 陌生，不能只靠通用知识可靠完成。
- 需要外部资料、引用、长篇报告、争议梳理或高影响判断。
- 用户只有一个大主题，还不知道真正值得回答的问题。
- 已搜到很多材料，但无法判断哪些应该进入正文。

纯故事、低风险观点短文、只改语气、用户已提供充分且可定位的材料时，可以只建立最小根问题，不必制造完整研究仪式。

本协议描述的是一个主 Agent 内的连续工序。视角不等于必须创建独立 Agent；即使宿主支持并行，圆桌主持仍要维护唯一案卷和最终裁决。

## 2. 先画视角地图

把“我要写 X”改写成一个与读者收益有关的根问题。例如，不问“AI 写作是什么”，而问“个人创作者怎样借 AI 提速，同时不把核心判断外包出去”。

围绕根问题选择 3–5 个会真正改变答案的视角。视角从任务生成，不使用固定专家名单凑数。可考虑但不必全用：

- 不同利益相关者看到的收益与代价
- 机制、因果链和替代解释
- 历史变化、当前状态与未来约束
- 对照案例、基线和可比对象
- 失败方式、反例、边界条件与不适用场景
- 从理解到行动所需的步骤、成本和条件

每个视角必须产生至少一个不同的问题，并说明“若不回答，会让文章在哪个判断上变浅或失真”。合并同义视角；删除与读者目标无关、只是在换角色口吻的视角。

视角地图是动态的。新资料只有在揭示新变量、冲突、边界或未知时，才新增视角；不要因搜到一篇文章就无限长枝。

## 3. 再建问题树

把视角转成可研究、会影响文章的问题，分为：

- `essential`：不回答就无法支持核心命题或会误导读者。
- `supporting`：帮助解释、举例、比较或转化为行动。
- `exploratory`：可能带来新角度，但缺失不会阻止成稿。

好问题应同时满足：答案会改变正文；可以指出需要什么证据；不是一个换皮关键词。给每个问题记录：

- 为什么要问，它影响哪个决策、主张或章节
- 期望找到的证据类型与优先来源
- 当前状态：`open`、`partial`、`answered`、`conflict`、`out_of_scope`
- 已关联的主张、来源和答案摘要
- 下一步最小追问；没有必要就停止

不要提前假设所有问题都有确定答案。问题无法验证时，允许把结论缩小、保留分歧或明确排除在本稿范围外。

## 4. 制定研究计划与预算

检索前先排序问题，并把可共享来源的问题放进同一研究回合。研究计划至少写清：先查什么、为什么、优先去哪里、什么结果会触发追问、何时停止。

默认预算是控制成本的软上限，不是质量证明：

| 模式 | 默认研究形态 |
|---|---|
| 快速成稿 | 一个内部根问题，只查必要事实；最多一轮针对性追问 |
| 完整圆桌 | 3–5 个视角、3–7 个核心问题；先广后深，最多两轮缺口追问 |
| 深度会议 | 先做广度扫描，再对核心冲突和高风险主张深入；扩大范围前设置检查点 |
| 单席研究 | 严格停在用户指定的研究问题与交付范围内 |

当继续研究需要付费、登录、上传私人材料、显著扩大时间/费用或改变文章方向时，交给用户决定。普通公开资料检索按宿主规则执行，无需为了流程感反复确认。

## 5. 循环研究而不是堆资料

每个研究回合执行同一闭环：

1. `Plan`：选择本轮最重要的 1–3 个问题和来源策略。
2. `Retrieve`：优先获取可定位的一手、官方或专业来源。
3. `Distill`：记录来源实际回答了什么、没有回答什么、限制和独立来源组。
4. `Update`：更新问题状态、答案摘要、主张和证据台账。
5. `Reflect`：判断新信息是否改变论点、范围、置信度、反例或下一问。
6. `Stop/Continue`：只有存在会改变成稿的缺口时才进入下一轮。

资料摘要不能直接拼成正文。每条来源必须至少做到一件事：支持主张、反驳主张、限定范围、提供必要案例，或暴露未知。做不到就作为线索或删除。

来源数量不等于可靠性。二十篇同源转载仍只算一个来源组；两条适用的一手证据可能比大量泛泛网页更有价值。

## 6. 通过研究覆盖门

进入提纲前检查：

- 每个 `essential` 问题已经 `answered`，或以安全措辞处理为 `partial/conflict/out_of_scope`。
- 核心主张能回溯到来源或清楚的推理链。
- 高风险事实已优先使用当前、可定位的一手/权威资料并做必要交叉验证。
- 关键反例、替代解释和适用边界没有被便利地删掉。
- 不相关来源已经剔除；没有为了展示研究量把支线塞进正文。
- 未解决问题已有处理决定：继续查、缩小、降格、删除、披露或请用户补充。

提纲应从“读者需要依次得到哪些答案”生成，而不是从“搜到了哪些资料”生成。一节尽量回答一个主问题；同一证据可以服务多个问题，但不能脱离原意反复利用。

## 7. 分段反思

长篇或深度模式在每个主要章节完成后检查五件事：

1. 本节是否真正回答了架构卡中的读者问题？
2. 关键结论是否由已映射的主张、来源或明确推理支撑？
3. 写作过程中是否新增了研究阶段没有出现的事实或因果表述？
4. 是否与前文重复，或提前透支了后文的功能？
5. 本节的新发现是否会使后续提纲失效？

发现问题时局部回退：缺证据回到对应问题，结构错位回到对应章节，措辞问题只改本段。没有新证据或新判断时，不反复重写同一节。

## 8. 用户可见结果与边界

普通写作任务只向用户展示最有决策价值的内容：根问题、2–5 个关键问题、重要缺口、采用的取舍和停止原因。只有用户要求、长期项目或机器处理时，才输出完整研究地图。

用户可以随时说“这个角度不重要”“优先查这一问”“这项只用我的材料”或“到这里就写”。主持总编更新地图和失效范围，不丢弃仍然有效的来源。

研究地图提高的是前期问题质量、证据可追溯性和长文结构稳定性，不保证自动产出可直接出版的文章，也不能替代专业领域审查、真实读者反馈或用户自己的立场判断。
