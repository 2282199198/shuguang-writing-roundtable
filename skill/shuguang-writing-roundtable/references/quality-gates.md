## 1. 先过硬门

下列任一失败，都不能用平均分抵消：

- 核心事实明确错误、重大过时、来源伪造或关键引语失真。
- 把推断、广告、用户笔记或单一传闻伪装成已证实事实。
- 未经许可泄露私人材料、抄录受限内容或执行外部动作。
- 标题承诺、正文结论和证据不一致。
- 用户明确要求保留的立场或段落被擅自改变。
- 声称交付了不存在或未经检查的文件、链接、发布结果。

硬门通过后再做质量评分。

## 2. 九项标尺

每项使用 0–3：

- 0：失败，妨碍发布
- 1：薄弱，读者明显受影响
- 2：合格，完成该项职责
- 3：突出，构成内容优势，并且有可定位证据

正式打分、版本对比或准备宣布“突出”前，完整读取 [quality-calibration.md](quality-calibration.md)。下面的定义用于判断方向，校准文件负责分值锚点、证据来源和强制上限。

### 1. 读者对齐

能否具体说出写给谁、解决什么处境？开头是否让目标读者迅速知道“与我有关”？不要把频繁使用“你”误当读者导向。

### 2. 认知收益

读者读后获得了新视角、新解释、可复用框架或被整理清楚的重要信息吗？不要把信息数量、情绪强度或反常识标题冒充认知收益。

### 3. 讲清讲透

核心概念有定义，推理没有关键跳步，抽象内容有必要例证，目标读者能够复述。讲透不等于讲全，不用把支线全部塞进来。

### 4. 主线结构

全文是否围绕一个核心问题推进？每节是否有明确功能和过渡？并列清单只有在关系真实并列时才成立。

### 5. 论证支撑

核心观点是否有足够证据、推理和边界？是否考虑重要反例、替代解释、因果与相关的区别？个人故事不能单独证明普遍结论。

### 6. 表达准确

范围、主体、时间、因果、概率和术语是否精确？是否存在绝对化、歧义、偷换概念或“研究表明”却无来源？准确不等于论文腔。

### 7. 阅读节奏

信息密度是否有张有弛，段落长短是否服务载体，开头是否及时入题，结尾是否在完成任务后停止？短句多不自动等于节奏好。

### 8. 可带走成果

读者能明确带走一个结论、方法、模型、判断标准、行动或有价值的情绪体验吗？结尾应收束成果，而不是复述全文或空泛升华。

### 9. 作者辨识度

内容是否有作者自己的观察、材料、判断或表达习惯？独特性可以来自观点、证据、案例或语言，不要求故意标新立异。

## 3. 体裁重点

不是每篇内容都要九项同权：

| 体裁 | 核心项 |
|---|---|
| 方法/干货 | 读者对齐、认知收益、讲清讲透、可带走成果 |
| 科普/知识 | 讲清讲透、论证支撑、表达准确、主线结构 |
| 观点/评论 | 认知收益、论证支撑、表达准确、作者辨识度 |
| 故事/随笔 | 读者对齐、主线结构、阅读节奏、作者辨识度 |
| 短视频口播 | 读者对齐、认知收益、主线结构、阅读节奏、可带走成果 |
| 商业/转化文案 | 读者对齐、论证支撑、表达准确、可带走成果，并另查合规 |
| 演讲/PPT | 主线结构、讲清讲透、阅读节奏、可带走成果 |

用户明确的目标可以改变重点，但不能绕过硬门。

## 4. 判定方法

默认达到：

- 所有适用项至少 2 分；
- 核心项中至少两项达到 3 分，或用户明确接受“合格但不追求突出”；
- `must_fix` 为 0；
- 不确定项已经删减、降格或披露；
- 标题、摘要、正文和交付格式彼此一致。

每项分数必须记录 `score_source=self/editor/reader/performance`、置信度和一条可定位证据。执笔者切换席位仍属于 `self`，不能冒充独立读者或独立编辑。没有足够样文、真实朗读、渲染抽查或文件检查时，执行校准文件中的分数上限。

只输出总分会掩盖问题，因此不计算总分。用户需要审稿报告时，给九项分数、证据、适用上限、最重要的 1–3 个问题、读者影响、修改方向和必须保留的优势。平台打开率、完播率、转化率和“读者喜欢”只能由真实数据或反馈证明。

## 5. 修订顺序

按影响面从大到小：

1. 读者、目的和核心命题
2. 主线与段落功能
3. 核心证据、反例和推理
4. 交付成果与结尾
5. 表达准确与风格一致
6. 节奏、标题和平台细节

先修大问题，再抠字句。读者审稿只指出问题、影响和方向；结构主笔执行修改。用户要求“只审不改”时，绝不擅自重写。

## 6. 常见机器腔与回归检查

警惕但不要机械禁用：

- 空泛的宏大开场和无证据的时代判断
- 连续使用“不是……而是……”制造假深刻
- 为了整齐强行凑三点、四步或对称句
- “首先/其次/最后”“综上所述”掩盖真实逻辑
- 每段都总结一次，结尾再重复一次
- 形容词和抽象名词堆叠，却没有人物、动作、条件或证据
- 伪造金句、故事、数据和“很多人都……”
- 过多标题把一篇文章切成碎片
- 为口语化加入无意义语气词

修订后回归检查：

- 被锁定内容是否未动？
- 新旧段落语气是否一致？
- 是否新增、删除或改变了事实主张？
- 引用编号、过渡和结论是否仍然对应？
- 删减后是否出现逻辑跳步？
- 平台改写是否改变原意或夸大承诺？

需要交付文件、锁定段落或正式验收时，配合 `scripts/validate_delivery.py` 与 `scripts/validate_revision.py`。脚本给出的重复句式、标题密度等结果只是预警，不能代替逐段判断。

标准模式做一轮主修订与一轮回归检查。若仍有结构性失败，回退对应阶段；不要用反复换词掩盖问题。
